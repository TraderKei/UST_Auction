KTB_AUCTION_DB 구현 내역 및 제약 검토
작성일: 2026-11-11

1. 실행 파일과 원천

KTB_AUCTION_DB.html을 Edge 또는 Chrome에서 직접 열면 됩니다.
DB_TABLE.xlsx의 Table, Column 및 숫자 시트 1~13만 읽어 만든 데이터 스냅샷입니다.
원본 HTML은 화면 구성의 참고로만 사용했으며 원본의 더미 수치, 기존 수집 데이터,
이전 구현의 계산 결과, 인터넷 자료는 가져오지 않았습니다.
엑셀의 문구는 데이터와 스키마 설명으로 취급했고 실행 지시로 해석하지 않았습니다.
원본 HTML과 엑셀은 수정하지 않았습니다.

13개 테이블, 1,674행을 HTML 안에 포함했습니다. 실행 시 네트워크 연결은 없습니다.
HTML만 다른 폴더로 복사해도 작동합니다. 엑셀을 변경해도 자동 반영되지는 않습니다.
화면 하단에 엑셀 SHA-256을 표시하여 사용한 원본 버전을 확인할 수 있습니다.
원본의 최신 입력일은 2026-11-10입니다. 이 날짜는 전체 테이블의 완결성 보증이 아닙니다.

2. 구현 화면

- 입찰 캘린더·블로터: 기간, 만기, 유형, 종목 검색, 월별 캘린더, 행 상세,
  공고/계획/결과 구분, 경쟁입찰 응찰배수와 테일 추이.
- 입찰결과 상세: 경쟁입찰 금액, 최저/최고/가중평균 금리, 부분낙찰률,
  원본 필드 전체, 정확히 연결되는 납입일, 금리 구조 및 추이.
- 수요강도 트래커: 월·만기별 응찰배수와 평균 테일, 상대 크기 히트맵, 추이.
- 발행계획 증감분석: 관측된 월간 국고·물가 계획, 만기별 전월 비교,
  종목별 원문 계획. 외평채와 교환은 경쟁발행 계획 합계에서 제외.
- 수급 분석: 경쟁/비경쟁/모집/매입/교환 관측 실적의 월별 참고표.
  실제 순공급은 원천이 부족하여 산출 불가로 표시.
- 비경쟁 인수 분석: 원문 인수명별 행사금액, 참여기관수, 인수율, 모집 결과.
- 공통: 다크/화이트 테마, 좁은 화면 대응, 현재 주표 CSV 내보내기,
  13개 테이블 전체 원본 검색 및 Column 사전 조회.

원본 예시의 한국어 6개 화면을 새 코드로 구현했으며 픽셀 단위 복제는 아닙니다.
외부 번역 파일에 의존하던 English 전환은 이번 독립 실행본에 포함하지 않았습니다.
영문 화면은 데이터 추가 없이 UI 번역을 추가하면 구현할 수 있습니다.
금리 구조는 실제 최저·가중평균·최고의 3개 값을 표시합니다. 시가·종가가 없는
자료로 금융시장 OHLC를 만들거나 최저금리를 역산하지 않았습니다.

3. 테이블 연결 및 계산

sheet 1 (165행): 경쟁입찰 결과. INFO_DATETIME_FROM을 입찰일로 사용.
sheet 2 (187행): 비경쟁인수 결과. EXECUTION_TO_DATE를 행사 종료일로 사용.
sheet 3 (63행): 발행계획. BID_DT를 입찰일, PAYMENT_DT를 납입일로 사용.
sheet 4 (39행): 교환계획. 발행종목/매입종목 조합을 원문대로 표시.
sheet 5 (35행): 발행계획 게시 목록. 원본 조회에 포함. 링크 대상은 열지 않음.
sheet 6 (93행): 매입결과. 종목별 ALLOCATION_AMOUNT 사용.
sheet 7 (140행): 교환결과. 종목별 ALLOCATION_AMOUNT 사용.
sheet 8 (28행): 모집방식 비경쟁인수 결과. BIDDING_DATE_FROM 사용.
sheet 9 (224행): 공고 게시 목록. 원본 조회에 포함. 링크 대상은 열지 않음.
sheet 10 (95행): 매입 공고. BIDDING_DATE_FROM 사용.
sheet 11 (155행): 교환 공고. EXCHANGE_BID_DATE_FROM 사용.
sheet 12 (412행): 발행 공고. BIDDING_DATE_FROM 사용.
sheet 13 (38행): 모집 공고. EXCHANGE_BID_DATE_FROM 사용.

경쟁 결과와 발행 공고는 정규화한 종목명, 입찰일, 경쟁입찰 유형이 일치할 때만
연결합니다. 정규화는 국고/물가/외평 + 금리코드 5자리 + 만기코드 4자리를
보존하고 뒤의 종목부호·괄호표기를 제거합니다. 일치하는 공고들의 납입일이
하나로 일치할 때만 결과 화면에 표시합니다. 결과가 없는 계획/공고는 별도
상태로 남깁니다. 비경쟁의 행사기간은 경쟁입찰일과 달라 임의로 결과에 합치지 않습니다.
비경쟁/매입/교환 만기는 같은 정규화 종목의 경쟁 결과 만기가 하나로 일치할 때만
연결하고, 그 외에는 미상입니다. 만기코드를 보고 최초 발행만기를 추정하지 않습니다.

공고의 0 날짜는 유효한 날짜로 표시하지 않습니다. 날짜가 없는 일반인입찰 공고
등도 원본 조회에는 모두 남아 있습니다. 캘린더에 안 보이는 것은 데이터 삭제가 아닙니다.
매입·교환 결과는 INPUT_DATE밖에 없어 입력일 기준으로 표시하고 그 사실을 명시합니다.
교환 공고에서 발행측 종목에 대응하는 결과가 없으면 공고로 남습니다.
sheet 4의 계획은 대응 키가 없어 교환 공고/결과와 병합하지 않고 별도 계획으로 남습니다.
따라서 캘린더의 표시 건수는 고유 입찰 회차 수가 아닙니다.

응찰배수 = BID_AMOUNT / INFO_AMOUNT (경쟁). 원문 BID_RATE(%)와 구분.
여러 입찰의 응찰배수 = 응찰금액 합계 / 예정금액 합계.
테일(bp) = (RESULT_MAX_RATE - RESULT_WA_RATE) × 100.
평균 테일 = 해당 입찰 테일의 단순평균.
낙찰률(%) = 낙찰금액 합계 / 응찰금액 합계 × 100.
전월 계획 증감 = 해당 만기 당월 계획 - 동일 조건 전월 계획.
전월이 조회기간 밖이어도 엑셀에 존재하면 비교합니다.
분모가 0이거나 자료가 없으면 —이며 실제 0은 0으로 표시합니다.
표/차트는 없는 기간을 보간하지 않습니다. 순공급 화면의 금액은 날짜 기준이 서로
다른 참고값이며 결제일 기준 실적이라고 표시하지 않습니다.

4. 구현이 불가능하거나 확정할 수 없는 항목과 해결 방법

가. 민평대비 스프레드
이유: 종목별 기준시점 민평금리가 13개 테이블에 없습니다.
해결: 엑셀에 종목 식별자, 평가일시, 평가기관, 민평금리와 비교시점 기준을 추가.

나. 종합 수요점수·강/약 등급
이유: 점수 산식, 가중치, 비교 모집단, 민평금리가 없습니다.
해결: 엑셀에 점수 정의·버전·결측 처리 규칙과 필요한 관측값을 추가.
현재 응찰배수와 테일만 제공합니다. 히트맵 색을 투자판단 등급으로 해석하지 않습니다.

다. 연간 발행목표, 연간 만기비중, 완전한 전년비·누계비
이유: sheet 3에는 2026년 5·6·8·9·10·11월 행만 있으며 7월과 전년 계획이 없습니다.
sheet 5의 게시 제목/링크만으로 연간 목표를 복원할 수 없습니다.
해결: 엑셀에 연도·월·만기별 완결된 계획과 연간 목표, 수정 이력을 추가.
관측된 월만 표시하며 일부 월 합계를 연간 목표로 바꾸지 않습니다.

라. 확정 월 발행계획 총액
이유: 2026-11-09 3Y에 두 종목이 각각 11,000, 2026-11-16 10Y에도 두 종목이
각각 11,000으로 기록되어 있습니다. 종목별 금액인지 공동 한도인지 구분 필드가 없습니다.
해결: auction_id, plan_group_id, amount_scope(종목/공동한도), 종목별 배정액,
계획 버전/유효 상태를 추가. 확인 전에는 해당 만기와 월 총액을 산출 보류합니다.
현재 검출 규칙은 동일 날짜·만기·금액 반복이며 모든 종류의 수정/중복을 증명하지는 않습니다.

마. 순공급과 순공급 워터폴
이유: 기존 발행잔액의 만기상환 원금, 교환의 발행·매입 양방향 실현금액,
모든 거래의 실제 결제일과 최종 발행액이 없습니다. 공고의 상환일은 잔액이 아닙니다.
해결: 종목별 잔액·상환원금, 결제일별 총발행액, 매입 소각액,
교환 발행측/매입측 실적과 거래 식별자를 엑셀에 추가.
교환 계획금액을 그대로 순공급에 더하거나 상환을 0으로 가정하지 않습니다.

바. 비경쟁Ⅰ·Ⅳ, 총발행 대비 비경쟁 비중, 정확한 행사율 분모
이유: sheet 2는 Ⅱ·Ⅲ만 제공하며 sheet 8과의 포괄·중복관계가 정의되지 않았습니다.
공고의 예정금액은 행사권 한도인지 실제 배정인지 명확하지 않습니다.
해결: 유형 코드/정의, 원입찰 식별자, 실제 발행액, 행사권 한도,
기간귀속 기준 및 모집방식 포함 여부를 엑셀에 추가.
현재는 원문 ACQUISITION_RATE만 표시하고 새 행사율이나 통합 비중을 만들지 않습니다.

사. 확정 금액 단위와 조원 환산
이유: Column은 sheet 6·7의 합계 필드 일부만 '억원'을 명시합니다.
나머지 금액 필드는 단위 메타데이터가 없습니다.
해결: 각 금액 컬럼의 통화, 단위, 액면/대금 기준을 Column에 명시.
현재 모든 공통 금액 표시는 원문 단위이며 임의로 10,000으로 나누지 않습니다.

아. 실시간 갱신·원문 PDF 세부·공휴일 처리
이유: 엑셀은 스냅샷이며 PDF 본문·영업일 달력·갱신 연결정보가 없습니다.
해결: 필요한 자료를 엑셀에 정형 테이블로 추가하고 재빌드.
현재 링크는 원본 문자열로만 표시하며 외부 자료를 자동으로 불러오지 않습니다.

5. 재생성 및 검증

소스: xlsx_terminal/build.py, template.html, style.css, app.js.
재생성: 프로젝트 루트에서 Python(openpyxl 설치 환경)으로
  python xlsx_terminal/build.py
엑셀의 Table/Column과 숫자 시트의 컬럼 일치 여부를 검증한 뒤 HTML을 생성합니다.
입력 파일명은 DB_TABLE.xlsx이며 기존 파일명을 임의 변경하면 빌드가 실패합니다.

브라우저 검증: Node.js + Playwright + 설치된 Edge 환경에서
  node xlsx_terminal/test_browser.cjs
Playwright가 번들 경로에 있는 환경은 NODE_PATH를 해당 node_modules로 지정합니다.

검증 항목: 6개 탭 전환, 1,674행 유지, 응찰배수/테일 계산, 0/결측/날짜 처리,
경쟁결과-공고 납입일 연결, 계획 중복 보류, 매입 종목합계와 회차합계 대사,
검색/기간/만기/지표 필터, 상세 창, CSV, 13개 원본 조회, 테마, 모바일 폭,
브라우저 JavaScript 오류 및 HTTP 요청 부재.
2026-11 경쟁 낙찰금액의 관측 합계는 49,000(원문 단위)로 대조했습니다.
금리·금액은 엑셀 자체의 정확성을 외부 자료와 대조한 것은 아닙니다.
